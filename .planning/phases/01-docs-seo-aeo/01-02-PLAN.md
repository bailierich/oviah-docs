<objective>
Add the two App Router file-convention discovery files: `sitemap.js` and `robots.js`.

Purpose:
- `sitemap.xml` (generated from `app/sitemap.js`) tells Googlebot, Bingbot, and Perplexity what pages exist and when each was last updated. Without it, AI Overviews and Bing/Copilot indexing are slower and less reliable.
- `robots.txt` (generated from `app/robots.js`) tells crawlers they're welcome AND points them at the sitemap. Required for Google Search Console verification (Plan 05's manual checkpoint depends on this).

Output:
- `app/sitemap.js` — default-exported async function returning the root URL plus all 22 article URLs with `lastModified` dates from frontmatter.
- `app/robots.js` — default-exported function returning `{ rules: { userAgent: '*', allow: '/' }, sitemap: 'https://docs.oviah.com/sitemap.xml' }`.

This plan is independent of Plan 01 — it does not touch `app/layout.jsx` or the article route or any MDX files. Both plans run in parallel in Wave 1. (Plan 01's `updatedAt` ISO normalization is technically a soft prereq for sitemap correctness but the sitemap function uses `new Date(... || new Date())` which gracefully degrades — sitemap won't crash even if Plan 01 hasn't run yet.)
</objective>

<discretionary_resolutions>
1. **JS, not TS**: Project is `.jsx`/`.js` for app code (`next.config.ts` is the only `.ts` file). Both new files are `.js` not `.ts`. Drop the `import type { MetadataRoute }` line — it's TypeScript-only. The Next.js docs explicitly show a `.js` switcher variant for both files (see `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/sitemap.md` line ~73 and `robots.md` line ~39).

2. **URL pattern**: The PRD's `https://docs.oviah.com/help/${a.slug}` is wrong for this codebase. Articles live at `/help/{category}/{slug}` (see Plan 01's discretionary_resolutions). Use `https://docs.oviah.com/help/${a.category}/${a.slug}`.

3. **Robots `rules` field shape**: The Next.js 16 docs (`robots.md` line ~28) show `rules` as a single object, not an array, when there's only one rule. Match that shape: `rules: { userAgent: '*', allow: '/' }` — NOT `rules: [{ ... }]`. Both forms are valid per the API reference but the spec shows the object form and so does D-05.
</discretionary_resolutions>

Create a NEW file `app/sitemap.js` with the following exact contents. This is a JavaScript file (no TypeScript types) because the project uses `.jsx` everywhere except `next.config.ts`.

```js
import { getAllArticles } from '@/lib/content';

export default async function sitemap() {
  const articles = getAllArticles();
  return [
    { url: 'https://docs.oviah.com', lastModified: new Date() },
    ...articles.map((a) => ({
      url: `https://docs.oviah.com/help/${a.category}/${a.slug}`,
      lastModified: (() => {
        const d = new Date(a.frontmatter.updatedAt);
        return Number.isNaN(d.getTime()) ? new Date() : d;
      })(),
    })),
  ];
}
```

Key points (each is locked):
- Default export, `async function sitemap()`. This is the App Router file-convention name (`sitemap.md` line ~46).
- Import alias `@/lib/content` matches existing usage in `app/help/[category]/[slug]/page.jsx`.
- `getAllArticles()` is synchronous in this codebase (no `await`) — see `lib/content.js`. Calling it without `await` is correct; the function itself is `async` only to align with `MetadataRoute.Sitemap`'s async-permitted contract per the Next.js docs.
- Root URL is the first entry per D-04.
- Article URL pattern: `/help/{category}/{slug}` — uses BOTH `a.category` AND `a.slug` (NOT `/help/${a.slug}` from the PRD which assumed a flat slug structure that this codebase doesn't have).
- `lastModified` MUST use the defensive IIFE form shown in the code block above. The naive `new Date(a.frontmatter.updatedAt || new Date())` form from the PRD is INSUFFICIENT: the `||` fallback catches falsy values only, NOT `Invalid Date`. Plan 01-02 runs in Wave 1 **in parallel** with Plan 01-01; if the sitemap task executes before Plan 01-01's `updatedAt` ISO normalization finishes, `new Date('March 2026')` returns `Invalid Date` (a truthy object), the `||` short-circuits to keep it, and every sitemap entry silently becomes the Unix epoch (`1970-01-01`). The IIFE form is the ONLY acceptable form: it explicitly checks `Number.isNaN(d.getTime())` before falling back to `new Date()`. Do NOT use the naive `||` form.
- Do NOT add `changeFrequency` or `priority` — D-04 doesn't require them and the PRD doesn't include them.
- Do NOT add a TypeScript return type (no `: MetadataRoute.Sitemap`).
